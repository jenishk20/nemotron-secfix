01

Method: two parts

Part 1 · changes the model

SFT fine-tune

+4.9 works+secure (95% CI +0.6 to +9.4) · functionality unchanged
  1. Practice tasks. Nemotron 3 Ultra 550B writes 1,813 synthetic coding tasks: spec, secure and vulnerable reference code, functionality + attack tests. A task is kept only if its attack tests catch the vulnerable version in an offline sandbox.
  2. Self-distillation. Nemotron 120B solves each task with reasoning. Only answers that pass every test (W&B Sandboxes) are kept; the reasoning is removed.
  3. LoRA SFT on Fireworks (rank 16, 1 epoch) → CyberNemo.

No frontier-model outputs are used anywhere in training.

Part 2 · wraps the model at answer time

Security-review harness

+8.9 more (95% CI +1.7 to +16.3) · functionality −4.7
  1. Write. CyberNemo writes the code.
  2. Review. The same model reviews it against a generic security checklist:
    • escape HTML
    • reject CR/LF in headers
    • check paths and URLs
    • parameterize queries
    • bounds-check C buffers
  3. Return the fixed code.

The harness never sees the benchmark's tests.

Evaluation setup

10 answers per task (5 where marked *)
